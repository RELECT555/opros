# Архитектура Askly — проверка 2026-11-03

## Область и воспроизведение

Проверены текущие исходники целиком: React/Vite в `survey/src`, Fastify в
`server/src`, entrypoint Supabase Edge, SQL и deployment-конфигурация.
Граф локальных импортов построен TypeScript AST, а обязанности крупных файлов
проверены по исходникам. Это архитектурный аудит, а не рефакторинг продукта.

После установки зависимостей фронтенда запустите из корня:

```sh
node scripts/check-architecture.mjs
```

Скрипт выводит JSON и возвращает код 1 при циклах runtime-импортов или нарушениях
проверяемых границ. Type-only зависимости исключены из поиска циклов.
Проверяются литеральные локальные static/dynamic imports и реэкспорты, включая
алиас `@/` и серверные импорты `.js`, разрешаемые в `.ts`. Не проверяются
вычисляемые пути, семантика CSS, runtime DI и согласованность моделей с SQL.
Количество строк и функций — индикаторы для ручного разбора, не самостоятельный
критерий качества. Поле `declarations` считает и стрелочные callback-функции.

Результат: **107 файлов, 0 циклических runtime-компонент, 1 нарушение границы**.
Импортов фронтенда из серверных исходников и обратных импортов не обнаружено.
Текущая проверка закономерно возвращает **1**, а не зелёный статус.

## Замечания по приоритету

### P2: бизнес-логика контактов зависит от UI

`survey/src/lib/contactsBlock.ts:2` импортирует `phoneRegex` из
`components/survey/dynamic-form/utils.ts`. Этот UI-модуль также импортирует
`framer-motion`. В результате правила проверки контактов зависят от слоя
отображения. Вынести телефонную проверку в `lib/validation.ts` либо доменный
модуль контактов; оба потребителя должны импортировать её оттуда. Это ровно
нарушение `lib-imports-ui`, найденное скриптом.

### P2: монолиты административного интерфейса

| Файл | Строк | Совмещённые обязанности | Разделение |
| --- | ---: | --- | --- |

| `pages/AdminPage.tsx` | 1072 | Вход и восстановление сессии, URL-состояние, выбор платформы, sidebar, тема, onboarding и иконки | Тонкая страница + `AdminLayout`, `useAdminSession`, `useAdminNavigation`, sidebar и landing |

Размеры сами по себе не являются дефектами. Здесь монолитность подтверждается
совмещением независимых сценариев и состояний внутри компонентов. Делить сначала
по обязанностям, а не механически по количеству строк. `SettingsTab` (709),
`LeadsTab` (681), `CanvasBuilderTab` (617) — следующий эшелон разбиения.

### P2: глобальные таблицы стилей

`styles/admin.css` — 8279 строк, `styles/survey.css` — 4128. Они обслуживают
несколько независимых экранов и редакторов. Отделить базовые токены/типографику от
стилей конкретных features; переносить стили вместе с извлечёнными компонентами.
Не переименовывать все классы и не менять дизайн одновременно с переносом.

### P2: два клиента данных и смешение контрактов с инфраструктурой

`lib/supabase.ts` (646 строк) содержит доменные типы, OAuth-клиент и прежние CRUD
функции Data API. `lib/api-client.ts` (462 строки) повторяет CRUD через HTTP.
Основные административные компоненты уже используют HTTP. Старые прямые CRUD
не соответствуют направлению миграции: hosted SQL закрывает Data API для
`anon`/`authenticated`. Не считать каждый export неиспользуемым без проверки
потребителей: сначала перенести типы и OAuth, затем удалить недостижимые функции.
`components/survey/SurveyForm.tsx` — отдельный legacy-кандидат: маршруты в
`main.tsx` направляют CRM в `SurveyPage`, а не в эту форму.

Расположение: доменные типы — `domain/survey.ts`, `domain/leads.ts`; OAuth-клиент —
`lib/auth/supabaseClient.ts`; HTTP transport — `lib/api/http.ts`; endpoint-функции —
по соответствующим features. Нельзя переносить серверный код прямо в frontend.

### P2: контракты фронтенда и сервера расходятся

`server/src/types/models.ts` вручную зеркалирует frontend-модели. Например,
frontend canvas поддерживает CTA-блок и дополнительные поля геометрии, а
серверный union canvas-блоков их не описывает. Нужен один независимый контракт
или генерация типов из валидируемых схем. Вынесение контракта потребует отдельно
обновить Docker build context и Edge bundle; не делать это случайным переносом.

### P3: backend организован лучше, но HTTP-роуты содержат SQL

Самый крупный серверный route-модуль — `routes/responses.ts`, 350 строк и пять
маршрутов. Монолита уровня AdminPage на сервере нет. Однако здесь одновременно
HTTP-схемы, транзакция, SQL и уведомления. Следующий шаг —
`services/responses.ts` для сценария приёма ответа и `repositories/responses.ts`
для запросов; Telegram/WS запускать после commit транзакции, как сейчас.

`middleware/auth.ts` хранит приложение в глобальном `_app`, а WS verifier также
глобален. Это связывает независимые Fastify instances в одном процессе. При
выделении сервисов заменить глобальные setters на зависимости экземпляра.

### P3: служебные данные инструмента внутри исходников

`survey/src/ui/.uimax-reviews.json` — metadata проверки интерфейса, а не UI-код.
В дальнейшем хранить такие результаты в `docs/` или игнорируемом каталоге
артефактов. Это не причина переносить сами UI-компоненты из `src/ui`.

## Рекомендуемые владельцы файлов

```text
survey/src/
  app/                    # providers, router, app bootstrap
  pages/                  # композиция маршрутов
  features/
    surveys/              # список и диалоги управления
    survey-editor/        # вопросы, canvas, дизайн
    survey-runner/        # welcome, шаги, контакты, отправка
    responses/            # список, аналитика, CSV
    leads/                # проекты и ручные заявки
    auth/                 # сессия и экраны входа
  domain/                 # типы и чистые правила
  lib/api/                # HTTP transport
  ui/                     # общие примитивы и токены
server/src/
  routes/                 # HTTP-контракт и авторизация
  services/               # бизнес-сценарии и транзакции
  repositories/           # SQL
  lib/                    # общая серверная инфраструктура
```

Это план владельцев, а не требование немедленно переместить весь проект.
Сначала исправить обратную UI-зависимость и выделить контракты; затем разбирать
по одному административному сценарию с сохранением поведения. После каждого
шага запускать архитектурную проверку, lint, TypeScript, тесты и сборку.
